name: dispatch
description: "승인된 티켓을 구현할 때: 티켓마다 새 하위 에이전트에게 맡기고 메인 세션은 보고와 diff만 검토한다"
---

티켓 순서대로 아래를 반복한다. 같은 폴더를 쓰므로 한 번에 티켓 하나만 진행한다.

1. 티켓을 열고 구현 에이전트를 띄운다. 가벼운 권장 모델로 티켓마다 새로 띄우고 이렇게 지시한다: "`AGENTS.md`와 이 티켓을 열고 `kit-change`, `tdd`로 끝내라. 요구사항은 `notes/requirements.md`에서 이 티켓의 규칙만 읽어라." 하위 에이전트를 띄울 수 없으면 이 세션에서 하고 보고에 그렇게 적는다.

2. 구현 에이전트의 보고 형식을 함께 준다.

   | 칸 | 내용 |
   |---|---|
   | 새로 보이는 것 | 사용자가 새로 볼 수 있게 된 것 한 줄 |
   | red | 명령, 실패 줄 |
   | green | 명령, 통과 수 |
   | 실제 실행 | 입력 → 출력 |
   | 설명할 곳 | 규칙을 맡은 파일:함수와 이유 한 줄 |
   | 미확인 | 돌리지 못한 것 |

3. 메인 세션은 보고와 이 티켓의 diff만 읽고 완료 조건을 하나씩 대조한다. 전체 테스트를 돌리고, 규칙의 예시 입력으로 실제 실행한다.

4. 지적이 있으면 같은 에이전트에게 돌려보낸다. 같은 지적이 두 번 반복되면 멈추고 사용자에게 보고한다.

5. 결과에 영향이 있는 티켓이면 `measure`의 "바꾼 뒤마다"를 한다.

6. `notes/system-map.md`를 연다. "지금 동작하는 것"을 고치고, 구조가 달라졌으면 해당 칸을 고친다.

7. 티켓의 파일만 커밋한다. 막히면 사용자가 칠 명령 한 줄을 준다.

8. 사용자에게 표를 전한다. 첫 줄은 "새로 보이는 것"이다. 사용자가 읽을 함수 하나를 "설명할 곳"으로 짚는다.

모든 티켓이 끝나면 남은 규칙과 미확인 항목을 보고한다.
