이 스킬은 구현 코드를 쓰지 않는다. 바꾸는 파일은 `notes/requirements.md` 하나다.

1. **환경 확인.** 사용자가 결과를 볼 곳에서 실제로 도는지 먼저 본다.
   - 테스트가 있으면 한 번 돌려 통과·실패 수를 적는다.
   - 화면이나 서버가 있으면 `0.0.0.0`에 띄워 사용자가 미리보기로 열 주소를 준다. 사용자가 열렸다고 확인할 때까지 이 단계를 끝내지 않는다.
   - 없으면 프로그램을 가장 작은 입력으로 한 번 실행한다.

2. **살피기.** README와 저장소 구조를 읽고 `notes/requirements.md`를 연다. 과제 한 줄, 제출물, 현재 상태를 적는다. 데이터가 있으면 행 수, 컬럼, 값 분포, 깨진 값, 이상한 기록을 세어 적는다. 완료 기준: 적은 값마다 돌린 명령이 있다.

3. **애매한 곳 찾기.** 같은 입력에 맞는 답이 둘 이상인 곳을 모두 찾는다. 일반 지식은 답과 출처를 적고, 이 회사·이 업무만의 규칙은 담당자 질문에 넣는다.

4. **담당자 질문.** 한 칸에 물음 하나만 담아 이 순서로 적는다.
   1. 쓰는 장면: 누가, 언제, 어디서 보고 무엇을 하는가
   2. 어느 시점이나 기준으로 판단하는가
   3. '됐다'의 기준과 실제 예시 하나
   4. 3단계에서 찾은 곳. 실제 값을 인용하고, 답에 따라 코드가 크게 달라지는 것부터
   5. 이번에 안 해도 되는 것
   6. 보안이나 외부 전송 제약

5. 보고한다: 환경 확인 결과, 현재 상태 세 줄, 질문 목록, 가장 먼저 물을 질문 하나.

사용자가 담당자 답을 주면 규칙표로 옮긴다. 빈 곳이 보이면 `grilling`을 연다. 규칙이 모이면 `$plan`을 권한다.
