## 1. 점검

1. 남은 worktree를 합치고 전체 테스트를 돌린다.

2. `.agents/skills/code-review/SKILL.md`를 열고 바뀐 것 전체를 한 번 리뷰한다. 버그와 요구사항 위반만 고친다. 구조 개선은 고치지 않고 `DECISIONS.md`의 한계에 적는다.

3. `.agents/skills/kit-deslop/SKILL.md`와 `.agents/skills/kit-no-comments/SKILL.md`로 정리한다. 저장소의 린트, 타입 검사, 순환 의존성 검사를 돌리고 전체 테스트를 다시 돌린다.

## 2. 대조

4. 규칙마다 구현한 파일:함수와 테스트를 찾는다. `notes/plan.md`가 구현과 다르면 구현에 맞춰 고친다. 구현하지 않은 규칙은 "안 만드는 것"에 이유를 적는다.

5. 주요 규칙마다 이 코드가 틀리는 입력을 하나씩 돌려 보고 `DECISIONS.md`의 한계에 적는다.

6. 제출물 목록을 대조하고, 실행 방법대로 처음부터 실행해 본다. 실행 방법이 제출물이면 README 끝에 덧붙인다. 커밋한다.

## 3. 설명

7. 사용자에게 자기 말로 설명해 달라고 한다. 답을 대신 쓰지 않고, 빈 곳이 있으면 찾아볼 파일:함수나 숫자만 알려 준다.
   1. 흐름: 입력 하나가 코드에서 어디를 지나는지, 계층 책임과 상태 소유자까지
   2. 왜: 주요 결정의 근거와 버린 안, 잰 값
   3. 안 만든 것: 무엇을 왜 뺐는지
   4. 한계: 어떤 입력에서 틀리는지, 테스트가 못 잡는 것

설명 내용은 파일로 남기지 않는다.
