# 초록인데 실제로는 못 지키는 테스트 패턴

항목마다: 어떤 모습인지 → 어떻게 찾는지(인벤토리 신호, 드러내는 변이) → 어떻게 고치는지.
인벤토리 플래그는 힌트이고, 증거는 변이다. 변이는 `scripts/falsify.py`로 돌린다.

## 이름이 말하는 이유로는 실패할 수 없다

**fixture 기본값이 분기를 건너뛴다.** 공용 fixture·팩토리가 가드가 검사하는 값을 이미 넣어 두어서
(`provider: "openai"`) 그 분기가 아예 실행되지 않고, 테스트는 어느 쪽이든 통과한다.
찾기: 가드를 지운다 → 그래도 초록. 고치기: 그 분기에 닿는 입력을 테스트가 직접 넣는다.

**엉뚱한 원인으로 빨개진다.** 부정 테스트가 4xx·예외를 기대하지만, 다른(앞선) 가드가 그걸 낸다
(대본이 없을 때 문장 id 검사가 422를 냄). 신호: `status-only`, `broad-raises`, `broad-throws`.
찾기: 이름이 가리키는 가드를 지운다 → 그래도 빨강. 고치기: 그 가드만 내는 오류 코드·메시지·필드를 단언한다.

**입력이 이미 계약을 만족한다.** 정렬·순서·위상 정렬 테스트인데 입력이 이미 정렬돼 있다. "가장 가까운 것"과
"첫 번째"를 구분해야 하는데 양쪽에 후보가 하나씩뿐이다. 찾기: 프로덕션 안에서 섞거나 뒤집는다 → 그래도 초록.
고치기: 까다로운 입력(뒤집기, 섞기, 동점, 한쪽에 후보 둘).

**격리를 실제로 확인하지 않는다.** 테넌트·워크스페이스 격리 테스트인데 다른 워크스페이스에 객체를 만들지 않는다
(무작위 UUID를 "다른 워크스페이스"로 씀). 찾기: 워크스페이스 필터를 지운다 → 그래도 초록.
고치기: 두 번째 워크스페이스에 실제 객체를 만들고, 그것이 안 보이거나 안 지워짐을 단언한다.

**부분 일치.** `toHaveTextContent("/workspace")`, `"설명" in readme`, 다른 곳에도 나오는 고정 문구에 `toContain`.
찾기: 그 글자를 만드는 코드를 지운다 → 그래도 초록. 고치기: 정확히 일치하거나 위치를 고정한 비교.

**단언이 삼켜진다.** fake·콜백 안의 `assert`를 프로덕션의 `except Exception`이 잡아 오류 이벤트로 바꾸거나,
테스트 안의 `try/except`가 삼킨다. 신호: `swallowed-assert`(테스트 쪽만). 찾기: fake가 확인하는 값을 깨뜨린다 →
그래도 초록, 로그에 `AssertionError`가 보인다. 고치기: fake는 호출을 기록만 하고, 호출이 끝난 뒤에 단언한다.

**항상 참.** `isinstance(x, bool)`, `len(x) >= 0`, `[] == list(range(0))`, 샘플이 0개여도 출력되는 메트릭 이름,
`not.toThrow()`. 신호: `weak-only`, `constant-assert`. 고치기: 값을 단언한다.

## 공허한 부정 단언

**호출될 일이 없는 것의 "호출 안 됨".** 테스트 대상이 import하지도 않는 함수, 또는 프로덕션 호출처가 아예 없는
함수에 `expect(fn).not.toHaveBeenCalled()`. 신호: `vacuous-negative`. 고치기: 긍정 결과를 단언하거나 지운다.

**만들어질 수 없는 글자의 "없음".** 어떤 프로덕션 파일에도 더 이상 없는 `x`(지운 CSS 클래스, 바뀐 키)에 대해
`"x" not in html` / `not.toContain("x")`. 신호: `vacuous-negative-string`(`--src` 필요). 고치기: 지금 그려지는 것을 단언한다.

**없앤 기능의 부재를 영원히 고정.** "예전 메모 칸이 없다"를 계속 확인. 다시 생길 위험이 실제로 있을 때만 남기고, 아니면 지운다.

## 하네스가 일을 대신한다

**autouse stub이 실제 엔진을 대신한다.** 모든 테스트가 stub 파서·정렬기·LLM으로 돌고 실제 경로는 테스트가 없다.
고치기: 하류 테스트가 기대는 stub 충실도 테스트는 남기고, 실제 경로 스모크 테스트를 하나 추가한다(비용을 먼저 잰다 —
1초 안쪽인 경우가 많다).

**테스트가 프로덕션을 다시 만든다.** 자기만의 리다이렉트 표를 선언하는 라우터 테스트, 스스로 `rollback()`을 부르고
롤백된 상태를 단언하는 테스트, 어떤 시그니처든 받는 `**kwargs` fake. 찾기: 프로덕션의 표·시그니처를 바꾼다 →
그래도 초록. 고치기: 프로덕션 객체를 import해서 직접 돌린다.

**손으로 만든 fixture가 실제 와이어 형태와 다르다.** 실제 생산자가 내지 않는 dict 키, 단계 전체를 조용히 건너뛰게
만드는 가짜 바이트(`%PDF-1.7\n%fake`), 프론트 테스트에 복사해 넣은 백엔드 데이터 500줄. 찾기: 실제 생산자를 한 번
돌려 키를 비교하고, 실제 샘플 하나를 넣어 본다. 고치기: 실제 생산자에서 fixture를 만들거나 공유 스키마를 쓴다.

**mock된 경계가 레포 사이의 계약 깨짐을 가린다.** 프론트 서비스를 mock해서 백엔드가 엔드포인트를 지웠는데도
테스트는 초록. 생산자·소비자 JSON(CLI 출력 한 줄, `units.json`, `offsets_ms`)을 양쪽 다 테스트하지 않음.
고치기: 공유하는 형태마다 계약 테스트 하나 — 양쪽이 같은 스키마·fixture를 읽거나, 소비자 테스트가 생산자의 실제 출력을 읽는다.

## 테스트가 코드를 살려 둔다

호출처가 테스트뿐인 함수·클래스(리팩터 뒤에 남은 것). 신호: `covers-test-only-code`(`--src` 필요; 부수효과 import와
데코레이터 등록은 사용으로 친다). `grep`과 `git log -S<이름>`(마지막 호출처가 언제 사라졌나)으로 확인한다.
버려진 코드 → 테스트와 코드를 함께 삭제(코드 삭제는 주인이 승인). 아직 연결 안 된 단계적 기능(최근, 로드맵에 있음) → 미결.

## 같은 증명의 반복

두 파일이나 두 층에서 같은 입력 + 같은 단언(클라이언트 테스트와 단계 테스트가 둘 다 "키 없음 → 오류" 확인,
공통 로직을 제공자마다 다시 확인, 단위와 통합에 같은 카탈로그 값). 신호: `duplicate-body`,
`prefix-duplicate`(본문 전체가 다른 테스트의 앞부분인 테스트). 가장 바깥의 실용적인 경계에 있는 것을 남기고,
고유한 단언은 옮기고, 나머지는 지운다.

## 선언이 동작인 척한다

레지스트리 값, 함수 시그니처, `__all__`, 필드 기본값, 호출 모양을 다시 적어 두는 테스트. 그 선언 자체가 계약일
때(공개 API 표면, 와이어 형식, 마이그레이션, 주인이 계약으로 여기는 비용 관련 기본값)는 남긴다. 아니면 그 선언이
약속하는 동작을 따라가 그것을 테스트한다.

## 설정값에 묶여 있다

로직은 그대로인데 바뀌는 튜닝값(임계값, TTL, 모델 이름, 한도)을 하드코딩한 테스트. 고치기: 테스트가 seam을 통해
자기 한도를 정하거나, 설정 출처에서 값을 읽어 그 양쪽을 찔러 본다.

## 새는 것과 위험한 것 (테스트가 좋아도 고친다)

- 레포 트리에 쓴다(상대 경로 저장소, `data/objects/...`), 설정된 DB에 커밋한다, 실제 브로커에 발행한다.
  스위트를 돌린 뒤 `snapshot.py check`를 하고, 돌리기 전에 설정의 기본 URL을 읽는다.
- 실패하지 않고 멈춘다(조건을 기다리는 루프에 타임아웃이 없음).
- 가짜 타이머로 되는 곳에서 실제로 몇 초씩 잔다.
- 복사해 붙인 지원 코드(같은 fake 모듈 9벌) → 공용 fixture 하나로.
- 이미 없는 테스트를 "테스트됨"이라고 적은 문서. 테스트 파일의 안 쓰는 import는 지워진 테스트의 흔적이다.

## 변이 고르기 (싸고 잘 듣는 것)

가드 삭제 · 조건 뒤집기 · 필터 제거(`workspace_id`, `IS NULL`, `deleted_at`) · effect 제거(`useEffect` 본문,
`setState`) · ID·키 구성요소 하나 빼기 · 분리기·파서에서 일찍/빈 결과 반환 · 순서 바꾸기 · 변환 제거(색 채널 교환,
정규화) · 이동·리다이렉트 호출 삭제 · 삭제·수정 범위 넓히기. 전체 스위트가 다 통과시키는 변이는 그 자체로 발견 사항이다.

함정: editable install이나 `sys.path` 설정이 없는 테스트 파일은 사본이 아니라 원본 레포를 import한다 —
`falsify.py`의 사전 점검이 이걸 잡는다. 기본 인자로 묶인 상수는 모듈 속성을 patch해도 바뀌지 않아서, 메모리 안
"변이"가 거짓으로 살아남는다.
