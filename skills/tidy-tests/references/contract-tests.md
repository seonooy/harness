# 계약 테스트 설계

계약 하나를 믿을 만하게 지키는 테스트를 어떻게 쓰는지. 기준은 하나다: **그 계약을 깨는 변이가 들어오면 이
테스트가 빨개지고, 계약을 지키는 리팩터에는 초록으로 남는다.**

## 1. 진입점 — 사용자가 그 기능을 쓰는 가장 바깥의 실용적인 지점

- 백엔드: HTTP 엔드포인트(TestClient) 또는 서비스 함수. 실제 DB(일회용)까지 지나가게 한다.
- 프론트: 컴포넌트·훅을 사용자처럼 쓴다(testing-library: 화면 글자, 역할, 클릭·입력). 내부 state를 읽지 않는다.
- CLI·워커: 실제 입력 파일 → 출력 파일·종료 코드.
- 가짜로 바꾸는 건 바깥 경계뿐: 네트워크, LLM·외부 SDK, 시계, 파일 저장소, 브라우저 API.
  내부 협력자를 mock해야만 테스트가 된다면 진입점이 너무 안쪽이다.

## 2. 한 계약 = 테스트 하나 또는 표 하나

- 테스트 이름이 곧 계약 문장이다: `대본을 문장으로 나눈다`, `test_rejects_oversized_recording`.
- 같은 규칙의 여러 경우는 표로: 행이 늘어도 관리할 곳은 하나다.

```ts
// 전: 만들면서 쌓인 비계 5개
it('마침표에서 나눈다') · it('물음표에서 나눈다') · it('3.5 같은 소수는 안 나눈다')
it('배열을 돌려준다')                 // 타입이 이미 보장 → 삭제
it('trimSpaces가 앞 공백을 지운다')   // 내부 헬퍼, 아래 표가 이미 지나감 → 흡수

// 후: 계약 하나 = 표 하나
it.each([
  ['문장. 다음 문장', ['문장.', '다음 문장']],
  ['정말? 네', ['정말?', '네']],
  ['3.5초 뒤', ['3.5초 뒤']],
  ['  앞 공백. 끝', ['앞 공백.', '끝']],      // 흡수한 trimSpaces 경우
])('대본을 문장으로 나눈다: %s', (input, expected) => {
  expect(splitSentences(input)).toEqual(expected)
})
```

## 3. 단언 — 관찰 가능한 결과의 실제 값

- 응답 본문, 저장된 행, 화면 글자, 반환값, 만들어진 파일의 내용. 개수만 보지 말고 값까지(`len == 1`은 정규화가 깨져도 통과한다).
- 부정 계약은 **그 가드만 내는 것**까지 단언한다. 상태 코드만 보면 다른 가드가 같은 422를 내도 통과한다.

```python
def test_rejects_run_for_lecture_without_transcript(client, lecture_without_transcript):
    res = client.post(f"/lectures/{lecture_without_transcript}/runs", json={...})
    assert res.status_code == 422
    assert res.json()["detail"]["code"] == "TRANSCRIPT_MISSING"   # 이 가드만의 코드
```

- "호출 안 됨"·"없음" 같은 부정 단언은 그 대상이 실제로 호출될 수 있는 경로에서만 의미가 있다. 아니면 긍정 결과를 단언한다.
- 콜백 props의 호출 인자는 컴포넌트의 출력이라 단언해도 된다. 내부 함수의 "호출됨"은 결과가 따로 보이면 결과로 바꾼다.

## 4. 경우(표의 행) 고르기 — 변이가 빠져나갈 틈을 막는 입력

- 경계 양쪽: 한도 −1 / 한도 / 한도 +1. 테스트가 쓰는 한도는 테스트가 정한다(설정값을 하드코딩하지 않는다).
- 틀리기 쉬운 입력: 정렬 안 된 입력(정렬 계약), 같은 값·동점, 빈 값, 아주 긴 값, 유니코드(NFD 한글), 공백.
- 격리 계약: 다른 소유자(워크스페이스·사용자)의 **실제 객체**를 만들고, 그것이 보이지 않거나 지워지지 않음을 단언한다.
- 순서 계약: 입력을 뒤집거나 섞어 넣는다. 이미 정렬된 입력으로는 정렬을 증명할 수 없다.
- 행마다 "이 행을 지우면 어떤 변이가 살아남나"를 말할 수 있어야 한다. 말할 수 없는 행은 군더더기다.

## 5. fixture

- 판단에 필요한 값은 테스트가 직접 넣는다. 공용 fixture의 기본값에 기대면, 그 기본값이 가드를 건너뛰게 만들 수 있다.
- 실제 출력과 같은 모양이어야 한다. 가능하면 실제 생산자에서 한 번 만들어 쓴다(손으로 쓴 dict의 키가 실제와 다른 경우가 흔하다).
- 실제 경로가 싸면(실제 PDF 한 장, 일회용 DB) 대표 경로 하나는 실제로 돌린다 — 먼저 비용을 재본다.

## 6. 비계를 남기는 경우

경우가 폭발하는 순수 로직(파서, 계산, 상태기계, 레이아웃 알고리즘)은 계약 테스트가 대표 경로만 지나가고,
세부 경우는 그 함수의 단위 표로 남겨도 된다. 남길 때는 머리말에서 해당 계약에 묶는다.

## 7. 변이 설계 (mutants.jsonl)

계약마다 "이 약속이 깨지는 가장 흔한 실수"를 1~3개. 한 줄 = 변이 하나.

```json
{"id": "M1", "contract": "C1 PDF에서 고른 필기는 카드가 펼쳐진다", "file": "web/src/components/AiPanel.tsx", "find": "if (selected) setOpen(true);", "replace": "", "note": "선택 시 펼침 effect 삭제"}
{"id": "M2", "contract": "C2 내 필기는 저장했다 그대로 복원된다", "file": "web/src/lib/userAnnotations.ts", "find": "page_number: o.pageIndex + 1,", "replace": "page_number: o.pageIndex,", "note": "쪽 번호 기준 어긋남"}
```

- 잘 듣는 변이: 가드 삭제, 조건 뒤집기, 필터 제거(`workspace_id`, `IS NULL`), effect·setState 제거, ID 구성요소 빼기,
  빈 결과 반환, 순서 바꾸기, 변환 제거, 삭제·수정 범위 넓히기. 더 많은 예는 `patterns.md`.
- `find`가 파일에 여러 번 나오면 `nth`를 지정한다(도구가 모호한 변이는 거부한다).
- 동작을 바꾸지 않는 변이(동치)는 이유를 적고 뺀다.
