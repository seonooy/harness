description: "승인된 티켓을 구현할 때: 겹치지 않는 티켓은 worktree로 병렬 처리하고, 티켓마다 검토, 재측정, 커밋까지 끝낸다"
---

`notes/design.md`의 상태가 "승인됨"인지 먼저 본다. 아니면 멈추고 `$plan`을 권한다.

1. 티켓을 나눈다. 서로 막지 않고 바꿀 파일이 겹치지 않는 티켓은 병렬로, 나머지는 순서대로 둔다. 표로 보여 주고 사용자가 고르게 한다. 병렬은 세 개까지다.

2. **병렬.** 지금까지를 커밋한 뒤, `.worktrees/`를 `.git/info/exclude`에 넣고 터미널마다 칠 명령을 사용자에게 준다.

   ```bash
   git worktree add .worktrees/<이름> -b <이름>
   cd .worktrees/<이름> && codex '<티켓 경로>를 열고 AGENTS.md의 구현 규칙대로 끝내라. 끝나면 보고 표를 줘'
   ```

3. **순서대로.** 티켓마다 새 하위 에이전트에게 맡기고 이 세션은 보고와 diff만 읽는다. 하위 에이전트를 띄울 수 없으면 이 세션에서 하고 보고에 적는다.

4. 구현하는 쪽은 `AGENTS.md`와 티켓을 열고, `notes/requirements.md`와 `notes/design.md`에서 이 티켓에 필요한 칸만 읽어 `kit-change`, `tdd`로 끝낸다. 아래 표로 보고한다.

   | 칸 | 내용 |
   |---|---|
   | 새로 보이는 것 | 사용자가 새로 볼 수 있게 된 것 한 줄 |
   | red | 명령, 실패 줄 |
   | green | 명령, 통과 수 |
   | 실제 실행 | 입력 → 출력 |
   | 설명할 곳 | 규칙을 맡은 파일:함수와 이유 한 줄 |
   | 미확인 | 돌리지 못한 것 |

5. 메인 세션이 검토한다. 이 티켓의 diff를 완료 조건과 대조하고, 전체 테스트를 돌리고, 규칙의 예시 입력으로 실제 실행한다. 같은 지적이 두 번 반복되면 멈추고 사용자에게 보고한다.

6. 측정 기준이 있으면 같은 명령으로 다시 재고 `notes/design.md`의 측정 기록에 전후 값을 더한다.

7. `notes/design.md`의 "지금 동작하는 것"을 고친다. 구조가 달라졌으면 구조 칸을 먼저 고치고 사용자에게 알린다.

8. 티켓의 파일만 커밋한다. 막히면 사용자가 칠 명령 한 줄을 준다. worktree는 브랜치를 한 번에 하나씩 합치고 전체 테스트를 돌린 뒤 `git worktree remove`로 지운다.

9. 사용자에게 표를 전한다. 첫 줄은 "새로 보이는 것"이다. 사용자가 읽을 함수 하나를 짚는다.
