`notes/plan.md`의 상태가 "승인됨"인지 먼저 본다. 아니면 멈추고 `$plan`을 권한다. 티켓 번호를 받았으면 그 티켓을, 없으면 다음 티켓을 고른다.

## 티켓 고르기

첫 티켓은 혼자 돌린다. 그다음부터 서로 막지 않고 바꿀 파일이 겹치지 않는 티켓은 두 개까지 worktree로 돌릴 수 있다. 사용자에게 표로 보여 주고 고르게 한다.

```bash
git worktree add .worktrees/<이름> -b <이름>
cd .worktrees/<이름> && codex 'notes/tickets/<티켓>.md를 열고 AGENTS.md의 구현 규칙대로 끝내라'
```

`.worktrees/`는 `.git/info/exclude`에 넣는다. worktree 쪽은 `notes/plan.md`를 고치지 않는다.

## 티켓 하나

순서대로 할 티켓은 새 하위 에이전트에게 맡기고 이 세션은 보고와 diff만 읽는다. 하위 에이전트를 띄울 수 없으면 이 세션에서 하고 보고에 적는다.

1. 티켓을 열고 `notes/plan.md`에서 이 티켓에 필요한 칸만 읽는다.

2. `.agents/skills/tdd/SKILL.md`와 `.agents/skills/tdd/test-criteria.md`를 연다. 코드를 쓰기 전에 이 표를 낸다. 근거 칸은 기준의 한 구절이고 비워 두지 않는다. 승인된 플랜의 테스트 칸이 seam 합의이므로 다시 묻지 않는다.

   | 테스트 | 코드 종류 | 크기 | 근거 |
   |---|---|---|---|

3. 테스트부터 쓰고 red를 본 뒤 구현한다. 약속한 동작 하나에 테스트 하나, 같은 규칙의 여러 경우는 표 하나, 단순 코드는 짜지 않는다.
   - 완료 조건을 실행할 수 있는 확인으로 정한다.
   - 데이터 모양부터 정한다.
   - 가장 작은 diff로 끝낸다. 외부 입력 검증은 입력 경계에서 한 번 한다.
   - 버그는 처음 잘못된 곳에서 고친다. 같은 실패가 세 번 반복되면 `.agents/skills/diagnosing-bugs/SKILL.md`를 연다.
   - 플랜과 다른 구조가 필요하면 멈추고 `$plan`을 권한다.

4. 프로그램을 실제로 실행해 규칙의 예시 입력으로 확인한다.

5. 이 세션이 검토한다. 이 티켓의 diff를 완료 조건과 대조하고 전체 테스트를 돌린다. "위험" 티켓만 리뷰 에이전트를 한 번 쓴다. 같은 지적이 두 번 나오면 멈추고 사용자에게 묻는다.

6. `notes/plan.md`의 "지금 동작하는 것"을 고친다.

7. 이 티켓의 파일만 커밋한다. 막히면 사용자가 칠 명령 한 줄을 준다.

8. 보고한다. 첫 줄은 "사용자가 새로 볼 수 있게 된 것"이다. 그다음 실제 실행 결과, 미확인, 사용자가 읽을 함수 하나를 파일:함수로 짚는다.

## 병렬을 합칠 때

브랜치를 한 번에 하나씩 합치고 전체 테스트를 돌린다. 통과하면 `notes/plan.md`를 고치고 `git worktree remove`로 지운다.
