---

이 스킬은 코드를 바꾸지 않는다. 바꾸는 파일은 `notes/requirements.md` 하나다.

1. **환경 확인.** 사용자가 결과를 볼 곳에서 실제로 도는지 먼저 본다.
   - 테스트가 있으면 한 번 돌려 통과·실패 수를 적는다.
   - 화면이나 서버가 있으면 `0.0.0.0`에 띄워 사용자가 미리보기로 열 주소를 준다. 사용자가 열렸다고 확인할 때까지 이 단계를 끝내지 않는다.
   - 없으면 프로그램을 가장 작은 입력으로 한 번 실행한다.

2. **재기.** README와 저장소 구조를 읽고 `notes/requirements.md`를 연다. 과제 한 줄, 제출물, 현재 상태를 적는다. 완료 기준: 적은 값마다 돌린 명령이 있다.
   - 데이터: 행 수, 컬럼, 값 종류별 개수, 범위, 빈 칸·깨진 행, 짝이 안 맞는 기록, 반복
   - 서비스: 주요 경로의 현재 응답

3. **애매한 곳 찾기.** 같은 입력에 맞는 답이 둘 이상인 곳을 모두 찾는다. README에 없는 경계, 데이터의 예외, 코드의 이상한 분기, 실패 테스트가 가정하는 규칙을 본다.

4. **나누기.** 일반 지식은 답과 출처를 적고, 이 회사·이 업무만의 규칙은 담당자 질문에 넣는다. 완료 기준: 찾은 것마다 둘 중 한 곳에 있다.

5. **담당자 질문.** 한 칸에 물음 하나만 담아 이 순서로 적는다.
   1. 쓰는 장면: 누가, 언제, 어디서 보고 무엇을 하는가
   2. 어느 시점이나 기준으로 판단하는가
   3. '됐다'의 기준과 실제 예시 하나
   4. 3단계에서 찾은 곳. 실제 값을 인용하고, 답에 따라 달라지는 코드가 큰 것부터
   5. 이번에 안 해도 되는 것
   6. 보안이나 외부 전송 제약

6. 보고한다: 환경 확인 결과, 현재 상태 세 줄, 질문 목록, 가장 먼저 물을 질문 하나.
